PART B - create the 2 context files with Copilot 
Both files are written by Copilot, then CHECKED and corrected by you. Never keep AI output unread.
 
STEP 1 - create docs/DATA_FORMAT.md 
1. new chat (+), choose AGENT mode (it can create the file)
2. do NOT attach anything: Copilot reads the code itself
3. paste this prompt:
 
--- PROMPT START ---
Read js/storage.js, js/app.js and js/utils.js and create docs/DATA_FORMAT.md describing the
expense data used in this app.
 
Include:
1. The expense object: every field name, its type and an example value. Use the exact field names from the code.
2. The allowed categories, as defined in the code.
3. How dates are stored (format).
4. Where data is stored (the localStorage key name).
5. A section "CSV export" with exactly these rules:
   - columns in this order: date, category, amount, note
   - first line is a header row
   - amount with 2 decimals (example 250.00)
   - a note containing a comma or a double quote is wrapped in double quotes
   - file name: expenses-YYYY-MM.csv (month of the filtered list)
   - export only the currently filtered expenses
 
Keep the file under 30 lines. Do not invent fields that are not in the code.
Do not change any code. Create only this one file.
--- PROMPT END ---
 
4. approve the create-file popup, open docs/DATA_FORMAT.md
5. CHECK (never skip):
   [ ] ctrl+shift+F search each field name it wrote - every one exists in the code
   [ ] localStorage key name matches the code
   [ ] categories match the app
   [ ] CSV section has all 6 rules (Copilot sometimes drops one)
   [ ] no invented fields
6. fix by hand what is wrong, save (ctrl+S)
 
STEP 2 - create docs/ACCEPTANCE.md 
1. new chat (+), AGENT mode
2. drag docs/PROJECT_BRIEF.md into the chat box (the checklist comes from the brief)
3. paste this prompt:
 
--- PROMPT START ---
Using the attached PROJECT_BRIEF.md, create docs/ACCEPTANCE.md: an acceptance checklist for this app.
 
Rules:
- 8 to 10 lines, each a markdown checkbox (- [ ] ...)
- each line must be testable by a person in under 1 minute in the browser, with a clear pass or fail
- cover: every input and button has a visible label or accessible name; amount must be greater than 0
  and an empty amount shows an error message; month filter works; totals match the visible list for
  the selected month; data is still there after page refresh; empty list shows a friendly message;
  delete works; works at 600px width with no horizontal scrolling; CSV export contains only the
  filtered expenses
- no vague lines like "app looks good" or "works well"
Do not change any code. Create only this one file.
--- PROMPT END ---
 
4. approve, open docs/ACCEPTANCE.md
5. CHECK (never skip):
   [ ] 8 to 10 lines, each starts with - [ ]
   [ ] every line has a clear PASS or FAIL (can you test it in 1 minute?)
   [ ] no vague line - rewrite it or delete it
   [ ] nothing outside the brief (no login, no database, no charts)
6. save (ctrl+S)
